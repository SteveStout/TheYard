# Changelog

One line per shipped version, newest first. The number is the one the page
footer shows, and 1.0.0.N is the Nth build that reached the live site. How a
line gets here, and why there is only ever one sentence, is recorded in
ADR: The changelog under the Decision Records index. From 1.0.0.41 the top
line here is where the deploy reads the version from, so this file and the page
footer cannot disagree (ADR: The version comes from the changelog). One number
is missing, 1.0.0.39, skipped under the older formula when a red build consumed
a deploy run number.

- **1.0.0.50** (2026-09-03): 1.0.0.49 built the SQL Server backend and then shipped on SQLite, because the deploy asked Azure for the database server's address and the deploy's own identity is not allowed to read it, so the placeholder survived and the container correctly read a placeholder as no database; the address is composed from the name now, which is what it always was, and the deploy says out loud which store the container came up on rather than leaving it to whoever reads the health endpoint by hand (ADR-039 addendum).
- **1.0.0.49** (2026-09-03): The relational store is Azure SQL Database now, reached with no password at all: the server was created Entra-only so it has no SQL login to have one, and the container authenticates as the managed identity it already carried, which means the connection string in its environment is a server name, a database name and an authentication mode and nothing worth stealing; the schema itself moved out of C# into a SQL project that compiles to a DACPAC and is now the authority, with Entity Framework held to it by a conformance test and the running application stripped of the right to alter a table at all; and the schema is the current model done properly, with a length and a reason on every column, a decimal grade, a datetime2 auction start, a rowversion on bids, a real foreign key to the account and two relationships deliberately left unenforced, the first publish of which told us something no amount of C# would have: Identity's default 450-character keys put four primary keys over SQL Server's 900-byte clustered index limit (ADR-039, ADR-040, and ADR-041 walks it for a developer meeting either for the first time).
- **1.0.0.48** (2026-09-03): Bids belong to people now: accounts through ASP.NET Core Identity, a session that is a signed token in a cookie the page cannot read, and a bid keyed on the person as well as the vehicle, so two visitors on the live site can outbid each other and both be told the truth about it, with an account view that lists what you have bid on and whether you are still winning (ADR-037, and ADR-038 walks the setup for a developer meeting Identity and JWTs for the first time); and two flakes that predate this work went with it, one where the API tests bid on the auction closest to closing and lost it between reading the minimum and posting the bid about one run in three, the other where the search benchmark asserted an exact inequality under a doc comment claiming to be loose and failed at 95 ms against 73 ms with five suites running at once.
- **1.0.0.47** (2026-09-03): Photos are sized for the box they land in: the originals are 1280 wide and the card paints them at about 358, so a first load was pulling 2.3 MB to fill nine boxes and a phone was pulling exactly the same bytes as a desktop, and there is now a 480-wide copy of all fifty beside them, 91 per cent smaller each, chosen by the browser through srcset, with a test holding the photo manifest and the image directory to the naming the browser relies on (ADR-036).
- **1.0.0.46** (2026-09-03): The cheap half of what the review deferred, none of it a live defect and all of it the kind of thing that becomes one: the style job now actually runs before the other three, which its own comment had been claiming without a `needs` line to make it true; the test that holds a crash and a rejected query to one shape would have passed on two empty bodies and now asserts it compared something; the restart test matched a bid amount as a substring of a whole JSON document, where a thirteen-digit timestamp contains almost any five-digit number, and now parses the field; and the exception handler noticed that its writer can decline, which happens when a caller accepts only text, in which case the request is reset rather than answered and the log now says so (ADR-030).
- **1.0.0.45** (2026-09-03): The corrections from a staff review of the night's own diff, of which one was serious and visible: a collapsed sidebar hid thirty-five documents behind a control a mouse could not see, because a disclosure whose summary is screen-reader-only has no visible way to open it; the public health endpoint stopped repeating a storage failure's exception text, which is typically a filesystem path; bids are written to the store before memory so a failed write cannot leave a bid the caller was told had failed; an abandoned request answers 499 at Information instead of 200 at Debug, which is the difference between seeing an outage and not; and the accessibility scan now waits for the grid it is checking and opens the records index it was skipping (ADR-030, ADR-033, ADR-035).
- **1.0.0.44** (2026-09-03): axe now holds six views to WCAG 2.1 AA inside the browser suite, and its first run found two serious contrast failures on the two most visible elements on the page, the reserve chip at 4.39 and the live countdown at 4.04, in a repository whose own palette test was passing because it holds the pairs somebody listed while a stylesheet composes whatever it likes; both colours were deepened rather than the threshold lowered, and the palette test gained the two pairs it was missing (ADR-035).
- **1.0.0.43** (2026-09-03): The catalogue and the bids moved into SQLite through EF Core, with the schema applied by migration at startup and the tables seeded on first boot from the JSON files that used to be the catalogue, and not one line changed above the Infrastructure layer because both sources already sat behind ports; a bid now survives the process restarting, which a test proves by starting a second application against the same file, at a cost of about 1.4 seconds on a cold container and nothing at all on the path a request takes (ADR-033, and ADR-034 walks the setup for a developer meeting EF Core for the first time).
- **1.0.0.42** (2026-09-03): How this was built now sits in the About menu beside the README: it says outright that an AI agent wrote most of this application, names the criteria a reviewer should judge that by, points each one at a place in the repository, and gives most of its length to the times the work was wrong, including the three objections a reader would raise and what the counter-evidence actually is (ADR-032).
- **1.0.0.41** (2026-09-03): The version comes from this file's top line now rather than from the deploy's run counter, after a red build consumed run number 28 and left the footer saying 1.0.0.40 while the line written with it said 1.0.0.39, so a ship that forgets its changelog line fails instead of shipping a number nothing describes (ADR-031); and the failure nobody wrote code for finally answers properly, with a handler that keeps the message and the stack inside, returns the same problem shape as a rejected query, and an endpoint that throws on purpose so that path can be exercised in production instead of assumed (ADR-030).
- **1.0.0.40** (2026-09-03): Style stopped being a preference: four checks now fail the build (dotnet format, Prettier, oxlint, and the typecheck that was already there), each proven to fail on bad input, and the linter's first run found a derive-do-not-store violation in the component that serves the style document (ADR-028); the twenty-nine records moved out of four topic sections into one numbered index that opens on demand (ADR-029); the first CI run of the new style job then failed on the command that had just passed locally, which turned out to be the repository claiming CRLF line endings while storing LF, true on Windows and false on the Linux runner, now fixed in .gitattributes and enforced by both formatters (ADR-028).
